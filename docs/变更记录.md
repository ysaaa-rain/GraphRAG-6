- 配置：生成模型使用 DeepSeek `deepseek-v4-flash`（OpenAI 兼容接口），embedding 使用百炼 `text-embedding-v4`（1024 维）；测试文本为 README 前 40 行生成的单个 `.txt` 文档。
- 索引进度：`load_input_documents`、`create_base_text_units`、`create_final_documents`、`extract_graph`、实体描述总结和社区划分等步骤均可完成，百炼 embedding 单次调用成功。
- 失败步骤：`create_community_reports`（社区报告生成）对全部 4 个社区返回 HTTP 400：`This response_format type is unavailable now`。
- 失败链：社区报告全部为空 → 后续合并空报告时抛出 `KeyError: 'community'` → `Pipeline error ... Pipeline complete`。
- 根因结论：GraphRAG 3.1.2 的社区报告抽取把 Pydantic 响应模型作为 OpenAI `json_schema` 严格结构化输出发送；DeepSeek API 目前只支持 `{"type": "json_object"}`，不支持 `json_schema` 类型，因此请求在接口层被拒绝，与模型质量或本地配置无关。
- 相关性说明：百炼/DashScope 的 OpenAI 兼容接口同样以 `json_object` 为主，切换 embedding 或百炼 Qwen 生成模型不能直接解决该问题；需对 GraphRAG 本地调用层降级为 `json_object` 后自行校验结构，或改用支持 `json_schema` 的模型。
