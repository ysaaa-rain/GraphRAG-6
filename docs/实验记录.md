### 首轮 Local 查询

问题：

> 这批 Enron 邮件样本中，哪些关键人物和组织被讨论？他们分别涉及哪些业务或日常事务？

执行方式：

```bash
set -a
source .env
set +a
python -m graphrag query \
  --root experiments/enron_s0 \
  --method local \
  --response-type '回答中列出关键人物、组织和主题，并说明证据来源' \
  '这批 Enron 邮件样本中，哪些关键人物和组织被讨论？他们分别涉及哪些业务或日常事务？'
```

结果：

- 命令成功返回答案，端到端耗时约 127.14 秒。
- 查询使用 Qwen 本地 embedding 成功，查询日志中的 embedding 请求失败数为 0。
- 答案能够列出 Enron、Continental Airlines、British Airways 等组织和多名参与者，并给出 `Entities`、`Relationships`、`Sources` 引用标记。
- 答案覆盖了燃料管理、天气衍生品、供应商协议、加州能源政策、会议和参观安排等主题。
- 当前只证明链路和证据标记可用，不证明答案全部事实正确，也不证明 GraphRAG 优于 Vector RAG；S0 尚未建立人工 ground truth。

### 兼容性问题与处理

DeepSeek V4 Flash 接受 JSON-object response format，但拒绝 GraphRAG 默认发送的 JSON Schema response format。项目在 `packages/graphrag/graphrag/index/operations/summarize_communities/community_reports_extractor.py` 中改为请求 JSON-object，并在本地用 `CommunityReportResponse` 做 Pydantic 校验。处理后社区报告完整生成，后续建库日志无失败响应。

### 当前限制

1. S0 只有 30 封邮件，不能代表完整 Enron 语料。
2. S0 问题只有首轮 pilot 查询，尚未形成 20–30 题 ground truth。
3. 尚未建立独立 Vector RAG 和 Hybrid RAG 基线，不能计算 Graph 效果差异。
4. 图谱实体和关系尚未完成人工抽样审计，模型输出中的关系必须回到源邮件核对。
5. 当前 macOS 使用 MPS；跨 Windows 复现时必须重新记录设备、软件版本和配置哈希，且同一次建库/查询仍要保持一致。
