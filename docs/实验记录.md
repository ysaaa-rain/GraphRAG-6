## 2026-09-07：Enron S0 GraphRAG 最小闭环

### 目的

验证从 Enron 邮件 JSONL 到 GraphRAG 索引、知识图谱、向量库和 Local Search 的完整链路，确认后续 Vector/Graph/Hybrid 对照所需的模型接入和结果记录方式可用。

| 字段 | 值 |
|---|---|
| 数据集 | Enron Email，CMU 2015-05-07 版本 |
| S0 输入 | 30 封邮件、3 个用户目录、33 个 text units |
| 数据文件 SHA-256 | `b3da1b3fe0369ec3140bb4fbce94702c33b7da810ec15d718b3fadf5cd748ca7` |
| 生成模型 | `deepseek-v4-flash`，API |
| embedding 模型 | `Qwen/Qwen3-Embedding-0.6B`，本地服务 |
| embedding revision | `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3` |
| embedding 维度 | 1024 |
| endpoint 配置 | `http://127.0.0.1:8000/v1` |
| 当前 macOS 设备 | `mps` |

### 首轮 Local 查询

问题：

> 这批 Enron 邮件样本中，哪些关键人物和组织被讨论？他们分别涉及哪些业务或日常事务？

执行方式：

```bash
set -a
source .env
set +a
python -m graphrag query \
  --root experiments/enron_s0 \
  --method local \
  --response-type '回答中列出关键人物、组织和主题，并说明证据来源' \
  '这批 Enron 邮件样本中，哪些关键人物和组织被讨论？他们分别涉及哪些业务或日常事务？'
```

结果：

- 命令成功返回答案，端到端耗时约 127.14 秒。
- 查询使用 Qwen 本地 embedding 成功，查询日志中的 embedding 请求失败数为 0。
- 答案能够列出 Enron、Continental Airlines、British Airways 等组织和多名参与者，并给出 `Entities`、`Relationships`、`Sources` 引用标记。
- 答案覆盖了燃料管理、天气衍生品、供应商协议、加州能源政策、会议和参观安排等主题。
- 当前只证明链路和证据标记可用，不证明答案全部事实正确，也不证明 GraphRAG 优于 Vector RAG；S0 尚未建立人工 ground truth。

### 兼容性问题与处理

DeepSeek V4 Flash 接受 JSON-object response format，但拒绝 GraphRAG 默认发送的 JSON Schema response format。项目在 `packages/graphrag/graphrag/index/operations/summarize_communities/community_reports_extractor.py` 中改为请求 JSON-object，并在本地用 `CommunityReportResponse` 做 Pydantic 校验。处理后社区报告完整生成，后续建库日志无失败响应。

## 2026-09-07：Enron S0 Vector-only pilot

### 目的

在不改变 S0 text unit、embedding 模型和问题文本的前提下，建立一个可重复的 Vector-only 基线入口，为后续 GraphRAG Local 和 Hybrid 对照提供公平的检索起点。

### 固定条件

- 检索语料：复用 GraphRAG S0 生成的 33 个 text units。
- 向量：复用 `text_unit_text` LanceDB 表中的 1024 维向量；查询向量通过同一个本地 Qwen 服务生成。
- 问题：`experiments/enron_s0/evaluation/questions.jsonl` 中的 12 题，顺序固定。
- 生成：同一个 `deepseek-v4-flash` API，非 thinking 模式，`max_tokens=4000`。
- top-k：5。
- 结果文件：`experiments/outputs/enron_s0/evaluation/vector_results.jsonl`，Git 忽略。

执行命令：

```bash
set -a && source .env && set +a
./.venv/bin/python scripts/run_vector_baseline.py \
  --max-tokens 4000 \
  --output experiments/outputs/enron_s0/evaluation/vector_results.jsonl
```

### 结果

- 12/12 题完成 5 条向量证据召回。
- 12/12 题返回非空答案，`answer_status=success`。
- 12/12 题 API `error` 为空；逐题保存引用 source path、相似度、延迟、finish reason 和 token usage。
- 本轮只完成 Vector baseline，不包含 GraphRAG 对照，也没有计算答案正确性、ROUGE-L、Evidence Recall 或 Multi-hop Success Rate。
- 首次使用 thinking 模式时曾出现空正文；GraphRAG 流式查询即使提高到 8000 仍不稳定，因此最终统一改用非 thinking 模式和 `max_tokens=4000`，避免混合参数。

### Vector pilot 当前限制

1. Vector 基线已经可运行，但 GraphRAG 和 Hybrid 尚未用同一问题集逐题运行。
2. 如果后续出现 `finish_reason=length`，必须作为截断结果单独统计，不能默认为成功。
3. 当前 12 题仍是 S0 pilot，不足以代表完整 Enron 语料或最终课程结论。

### S0 数据与图谱当前限制

1. S0 只有 30 封邮件，不能代表完整 Enron 语料。
2. 已建立 12 题六类 pilot 问题集和证据标注，但尚未扩展到最终 20–30 题 ground truth。
3. GraphRAG 和 Hybrid 尚未用同一问题集逐题运行，不能计算 Graph 效果差异。
4. 图谱实体和关系尚未完成人工抽样审计，模型输出中的关系必须回到源邮件核对。
5. 当前 macOS 使用 MPS；跨 Windows 复现时必须重新记录设备、软件版本和配置哈希，且同一次建库/查询仍要保持一致。

## 2026-09-07：GraphRAG Local 同题 pilot

### 目的

使用与 Vector 完全相同的 12 题、Qwen embedding、DeepSeek 模型、非 thinking 模式和 `max_tokens=4000`，运行 GraphRAG Local，形成第一轮逐题对照原始结果。

### 结果

- 12/12 题返回非空答案，`answer_status=success`。
- 每题保存 `Sources`、`Entities`、`Relationships` 引用编号、原始输出、延迟和错误状态。
- 会议安排问题能够同时发现不同邮件中的地点表述差异（50 M03 与 EB 3321），该冲突被保留为证据分析对象，不能直接判定为模型错误。
- 当前尚未把答案内容判为正确或错误；来源编号已映射回原始 `source_path` 并完成严格统计，下一步进行可接受证据集合和答案忠实度人工复核。

汇总命令：

```bash
./.venv/bin/python scripts/summarize_enron_results.py
```

当前严格 source-path 统计：Vector 平均证据邮件召回率为 `0.8333`，9/12 题覆盖全部当前标注证据，平均延迟约 `2.608s`；GraphRAG Local 平均为 `0.2917`，3/12 题覆盖全部当前标注证据，平均延迟约 `11.959s`。两边均为 12/12 非空成功。

这不是效果结论：当前统计按人工标注的精确 `source_path` 计算，GraphRAG 引用的相邻线程邮件可能支持同一事实但不等于当前主证据；D01 等全局题还出现答案有实体但缺少 Sources 引用的情况。后续需要扩充“可接受证据集合”、人工复核答案忠实度，并补充 Hybrid 结果。
