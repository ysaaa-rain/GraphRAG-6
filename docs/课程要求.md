> 文档性质：本文件前半部分只提炼课件《知识工程综合实践》的内容；后半部分是本组为了落实课件要求而制定的检查项。两者不能混淆。

原始课件已归档为：[课程要求.pptx](./参考资料/课程要求.pptx)。

老师补充提供的两张评分标准截图也已归档： [总评评分标准](./参考资料/评分标准-总评.jpg)、[阶段 1 评分标准](./参考资料/阶段1评分标准.jpg)。

## 一、明确要求

### 1. 课程组织与项目制要求

1. 采用项目制方式，4–5 人组成一个小组。
2. 小组自主提出要开发的系统功能，自主选题并完成系统设计与实现。
3. 项目不能与已有项目雷同。
4. 可以使用 AI 辅助编程，但必须理解和掌握生成的代码；答辩时如果讲不清楚 AI 生成代码，按不合格处理。
5. 使用 Gitee 或 GitHub 开源代码管理系统进行协同开发与代码管理。

### 2. GraphRAG 系统的最低组成与设计点

课件第 5 页要求 GraphRAG 系统至少包含三个大组件：知识图谱构建、检索器、LLM。

并要求明确选定以下三个设计点：

1. 实体与关系如何抽取。
2. 使用什么检索方式。
3. 以什么形式将知识注入 LLM。

课件给出的整体链路包括：

```text
文本 → 实体/关系抽取 → 图谱存储
                    ↘ 全文索引、向量索引、查询索引
文本存储、嵌入计算、图谱存储 → 检索器 → Retrieved KG → LLM
```

课件列出的检索方式或组合包括：基于文本、基于图谱、基于向量、基于向量 + 文本混合，以及 Vector、VectorCypher、Hybrid、HybridCypher。

### 3. 课件中的示例系统

课件第 6 页以《红楼梦》GraphRAG 系统为例，展示了三项设计：

- KG 构建：使用简单提取 prompt，加预定义本体模型。
- 检索器：四种检索器动态选择。
- 知识注入：直接提供知识。

这部分是课堂示例和设计参考，不等于本组必须原样复刻的最终方案。

### 4. Vector / VectorCypher 对比展示

课件第 7–8 页标题为“Vector/VectorCypher 对比”，通过界面截图展示两种检索方式的结果差异。课件没有给出可直接引用的量化指标或统计结论，因此本组不能把截图视觉差异直接写成“效果提升百分比”；需要在统一数据、统一模型和统一问题集下重新测量。

### 5. AI 辅助编程与质量检查

课件第 9 页强调：

- 小心直接生成代码带来的错误，不要直接接受生成代码，要有质量检查流程。
- 代码跑完测试再验收合并。

示例仓库地址：<https://gitee.com/tjudb/2026graphrag>。

### 7. 代码存档与版本管理

- AI 经常会写中间文件但最后不删除，应当注意清理无用文件。
- 阶段性使用 `git commit` 存档；被 Git 追踪的修改至少是可恢复、可溯源的，可以参考 `git blame` 和 `git bisect`。
- 阶段性存档可以为后续开发提供 baseline。
- 可以多开分支，并使用 `git revert`、`merge`、`rebase`、`cherry-pick`、`stash` 等方式兜底；commit 多不是问题。

## 三、答辩时必须能讲清楚的内容

每位成员至少应能说明：

1. 文本如何变成实体、关系、社区和索引。
2. Vector、Graph、Hybrid 三种检索的输入、输出和适用问题类型。
3. 检索结果如何进入 LLM 上下文，以及如何追溯证据来源。
4. 实验为什么公平，指标如何计算，结果是否具有统计意义。
5. 自己负责的代码、配置、测试和实验记录如何工作。
6. 一次典型错误是如何发现、修复、测试并通过 Git 留痕的。

### 1. 总评评分标准：100 分

| 评价大项 | 分值 | 老师评价要求 |
|---|---:|---|
| 一、创意与价值 | 15 | 项目应有明确的使用场景，体现一定的想法、领域特点或实际价值；能够说明为什么使用知识图谱，以及图结构在知识关联、多跳查询、组织信息或解释答案方面可能发挥的作用。 |
| 二、实现完成度 | 25 | 项目的核心流程和主要功能应能完整演示，大部分时间可以正常运行，对常见错误有基本提示。 |
| 三、Graph 效果 | 25 | 使用相同数据和少量代表性问题，对普通 RAG 与 GraphRAG 进行简单、基本公平的比较，并展示 2–3 个成功或失败案例，说明图是否帮助了关联、多跳、答案概述或可解释性。 |
| 四、界面表现 | 15 | 界面应能够支持主要操作，信息层级清楚、文字可读、交互基本顺畅，并能展示答案以及引用文本、相关实体关系图中的至少一部分。 |

### 4. 对当前项目的直接影响

阶段 1 不是只要求“代码能启动”，还要求拿出可解释的证据。因此 P1 阶段的最低交付物调整为：

- 一张说明数据、知识图谱、检索和生成关系的架构图。
- 一份数据来源、原始样例、处理前后变化和规模统计。
- 一个能启动、导入数据并完成最小问答闭环的运行入口。
- 3–5 个代表性问题，以及每题的检索内容、回答和合理性说明。
- 一页成员分工、当前进度、困难、剩余任务和下一阶段优先级。

总评阶段还必须追加：

- 2–3 个普通 RAG 与 GraphRAG 的成功或失败对比案例。
- 答案、引用文本和至少部分实体关系图的界面展示。
- 与实际 PPT 和现场演示一致的可运行版本。
- 对现存问题、局限和未完成项的诚实说明。
