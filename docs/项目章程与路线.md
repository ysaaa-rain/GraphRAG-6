# 项目章程与开发路线

> 文档性质：本文件是本组的执行章程，不把本组决策冒充为老师课件要求。若后续组内确认主题或资源发生变化，应在这里更新，并同步更新评测与数据文档。

## 1. 项目定位

本项目要构建一个能够解释 GraphRAG 工作过程、复现实验结果并支持 Vector/Graph/Hybrid 对照的知识问答系统。系统面向公开文本知识，输出答案时尽量保留证据来源和检索路径，便于老师理解、成员协作和后续调优。

## 2. 研究问题

核心问题不是“如何让 GraphRAG 看起来更复杂”，而是：

> 在什么类型的问题和数据结构下，显式实体—关系图能为 RAG 提供向量相似度之外的有效信息？这种收益是否足以抵消图谱构建、索引和查询带来的额外成本？

围绕这个问题，项目至少回答：

1. 对单跳事实问题，GraphRAG 是否会退化或保持稳定？
2. 对跨文档、多跳、全局主题问题，GraphRAG 是否提高证据覆盖和答案正确性？
3. Hybrid 是否比纯 Vector 或纯 Graph 更稳定？
4. GraphRAG 的收益来自图结构本身，还是来自更多 token、更多 LLM 调用或更好的提示词？
5. 图谱质量、检索配置、LLM 和数据规模分别对结果有什么影响？

## 3. 初版系统范围

### 必须完成

- 文本输入与切分。
- 实体、关系和必要的社区结构构建。
- 向量检索、图增强检索和混合检索至少各有可运行路径。
- LLM 知识注入与答案生成。
- 统一 benchmark 批量推理。
- Vector/Graph/Hybrid 结果、成本、延迟和失败样例的可追溯记录。
- 中文项目文档、测试和阶段性 Git 记录。
- 满足阶段 1 评分要求的 3–5 个代表性问题、数据处理前后样例和成员/进度说明。

### 暂不承诺

- 不在第一阶段追求自研图数据库或复杂前端。
- 不在没有实验数据之前声称 GraphRAG 必然优于 Vector RAG。
- 不把大规模原始数据、密钥、模型缓存或临时输出直接提交进 Git。

## 4. 目标与验收口径

### 工程目标

- 新成员可以按照文档完成环境准备、数据准备、索引、问答和评测。
- 任一结果都能追溯到代码 commit、配置、数据版本、模型、问题集和评测脚本。
- 每次合并都有测试或实验依据，文档描述与当前代码一致。

### 实验目标

首轮目标是建立可信对照，而不是预设胜负：

- 在 GraphRAG-Bench 上完成 Vector、Graph、Hybrid 三条可重复实验链路。
- 以复杂推理、上下文摘要和证据覆盖作为 GraphRAG 的重点观察指标。
- 以事实检索、延迟、LLM 调用量和估算成本作为稳定性与代价指标。
- 暂定优化目标：复杂推理或摘要主指标相对 Vector 基线取得至少 5% 的相对改善，同时事实检索不出现超过 2 个百分点的回退；该目标是本组的工程目标，不是预先写好的实验结论。

### 结果判定

若未达到优化目标，不修改数据或指标来制造提升，而是：

1. 按问题类型和数据规模分析失败。
2. 检查图谱质量和证据召回。
3. 报告 GraphRAG 的适用边界、额外成本和下一步改进。

## 5. 开发路线

| 阶段 | 内容 | 交付物 | 状态 |
|---|---|---|---|
| P0 | 课程要求、远程仓库和基线核对 | 课程要求、基线说明、初始 Git 历史 | 已完成 |
| P1 | 环境验证与最小样例 | 环境说明、运行日志、最小索引和查询结果 | 下一步 |
| P2 | 数据资产准备 | 数据登记表、来源/许可/哈希、预处理脚本 | 计划中 |
| P3 | Vector 基线 | 固定 chunk、embedding、top-k、LLM 的向量 RAG 结果 | 计划中 |
| P4 | GraphRAG 与 Hybrid | 图谱构建、检索路径、知识注入和配置 | 计划中 |
| P5 | 统一评测与消融 | GraphRAG-Bench 结果、成本、延迟、失败分析 | 计划中 |
| P6 | 可视化与前端包装 | 图谱视图、指标图表、可演示问答界面 | 计划中 |
| P7 | 汇报与答辩材料 | 架构图、实验表、复现说明、成员分工 | 计划中 |

阶段 1 的验收以老师评分截图为准：项目立意与设计 25 分、数据准备 20 分、基本跑通 35 分、进度与汇报 20 分。具体逐项要求见[课程要求与逐项检查表](./课程要求.md)。

## 6. 近期下一步

1. 在当前基线 commit 上完成依赖和测试可运行性检查。
2. 用 GraphRAG-Bench Novel 的小样本建立数据格式适配，不立即跑完整集。
3. 先跑通基线的 indexing、local search、global search 和 basic/vector search。
4. 固定第一版实验配置，并把所有参数写入配置文件和实验记录。
5. 再实现统一的 Vector/Graph/Hybrid 输出格式和评测入口。

## 7. 主题选择说明

老师课件用《红楼梦》作为示例，因此“中文经典文学/红楼梦”是当前应用案例候选；GraphRAG-Bench 的 Novel 和 Medical 则作为统一 benchmark 候选。最终应用主题应由小组确认，并在本文件、数据资产清单和展示方案中同步更新。
