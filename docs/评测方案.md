# 评测方案

> 状态：方案已建立，正式对照分数尚未产生。Enron S0 已完成建库和一次 Local 查询，仅作为链路验收，不作为 Vector/Graph 效果结论；原始输出、参数和结果汇总放到实验产物目录并用 commit 关联。

## 1. 评测目的

同时满足两条证明路径：

1. 在实际案例中，对比 Vector RAG 与 GraphRAG 的效果差异。
2. 在明确 benchmark 上，用统一指标测量 GraphRAG 的提升、退化、代价和适用边界。

本组采用“两条路径并行”：GraphRAG-Bench Novel/Medical 负责统一、可复现的标准测评；Enron Email 负责验证大规模开放邮件上的检索路径、图结构、跨文档关系和实际问答效果。

## 2. 主要 benchmark

主要 benchmark：<https://github.com/GraphRAG-Bench/GraphRAG-Benchmark>

## 3. Enron 实际应用评测

Enron Email 单独建立数据版本、问题集和结果表，不与两个 benchmark 的官方分数混成一个平均数。

- 优先使用规模足够大的开放邮件语料，并记录来源、许可证、版本、哈希、邮件数、字符/token 数和图谱规模；对最终采用的具体规模不预先写死，先通过数据准入核验。
- 设计 20–30 道跨邮件问题，覆盖单事实、多实体关联、多跳推理、全局总结、图结构帮助有限和幻觉风险六类。
- 每题保存参考答案、原文证据、标准实体、标准关系/路径以及是否预期需要图结构。
- 最终选取 3–5 道代表性问题展示 Vector 检索文本、GraphRAG 实体/关系/路径、最终答案、引用、成功原因和失败原因。
- `Multi-hop Success Rate` 与 `Evidence / Path Recall` 是本组对 Enron 实际应用定义的补充分析指标，不宣称它们是 GraphRAG-Bench 官方指标；benchmark 结果仍以官方数据和官方评测协议为准。

S0 首版 12 题固定 pilot 已保存到
[`experiments/enron_s0/evaluation/questions.jsonl`](../experiments/enron_s0/evaluation/questions.jsonl)。每题包含类别、参考答案、证据邮件、关键实体、关键关系、预期图结构帮助程度和证据不足边界。它只用于先验证逐题结果记录和三种系统的公平运行；正式 Enron 评测仍需扩展到 20–30 题，并经过第二轮人工复核。

《红楼梦》不属于当前正式实际应用领域，只保留为早期候选记录。

Enron S0 的实际运行摘要、索引规模、模型 revision、首轮问题和限制见[实验记录](./实验记录.md)。

## 4. 对照系统

| 系统 | 检索上下文 | 变化变量 | 目的 |
|---|---|---|---|
| Vector | 文本 chunk 的向量 top-k | 无图结构 | 建立最低成本基线 |
| Graph | 实体、关系、社区和关联文本 | 引入图结构 | 测量图结构对多跳/全局问题的贡献 |
| Hybrid | 向量 + 图结构 + 文本 | 融合两类检索证据 | 观察折中方案是否更稳定 |
| Hybrid + reranker | 向量 + 图结构后统一重排 | 增加重排器 | 作为后续优化条件，不覆盖前三种原始基线 |

公平性约束：三种系统尽可能使用相同原文、chunk 规则、embedding、LLM、temperature、回答格式、问题顺序、评测模型和重试策略；每种方法的上下文 token 预算和调用次数单独记录。

## 5. 指标

### 5.0 问题类型的适用范围

问题集至少包含六类，每类都要有标准答案和证据标注：

- A 单事实：检查基本事实召回。
- B 多实体关联：检查多个实体的关联答案。
- C 多跳推理：检查跨文档或跨关系路径。
- D 全局总结：检查社区级信息聚合。
- E 图结构帮助有限：检查 GraphRAG 是否增加不必要代价。
- F 幻觉风险：检查无证据、歧义或错误前提下的忠实度和拒答。

第一版内部 pilot 目标为每类至少 5 题，共 30 题，用于验证本组字段和流程。正式实际领域各自使用 20–30 道自建问题；GraphRAG-Bench 的官方问题类型、数量和评测方式以其仓库为准，不能把本组六类问题表述成官方题型定义。

### 5.1 答案生成指标

GraphRAG-Bench 评测代码中涉及的主要指标：

- Answer Correctness：由事实性 F1 与语义相似度加权组成；当前代码使用 `0.75 × factuality + 0.25 × semantic similarity`。
- ROUGE-L：答案与参考答案的最长公共子序列 F1，主要用于事实检索和复杂推理。
- Coverage：参考答案中被生成答案覆盖的事实比例，主要用于上下文摘要和创意生成。
- Faithfulness：生成答案中的陈述有多少可以由检索上下文直接支持。

### 5.2 检索和图谱指标

- Context Relevancy：上下文对当前问题的相关程度，统一代码按 0–2 评分后归一化。
- Evidence Recall：检索上下文覆盖标准答案证据的程度。
- Multi-hop Success Rate：需要多跳路径的问题中，检索到完整标准路径并生成正确答案的问题比例。完整路径至少要覆盖标准路径上的关键实体和关系。
- Evidence / Path Recall：标准证据片段或标准实体—关系路径中，被检索上下文/子图召回的比例；多跳题分别报告证据召回和路径召回，不能只看最终答案分数。
- Indexing：图密度、连通性、聚类系数、实体分布和关系分布等结构指标。

### 5.3 工程指标

- 单条查询延迟和 P50/P95。
- 索引总耗时、查询总耗时。
- LLM 输入/输出 token、调用次数、失败重试次数和估算费用。
- 图谱节点数、边数、社区数、孤立节点比例和重复实体比例。
- 失败率、空检索率、超时率和答案无法由证据支持的比例。

## 6. 实验矩阵

第一轮只改变检索路径，不同时改变多个因素：

| 维度 | 第一轮设置 | 后续消融 |
|---|---|---|
| 数据 | Novel 100 条样本 | Novel 全量、Medical 全量、Enron Email |
| LLM | 同一模型、固定版本 | 模型替换实验 |
| Embedding | 同一模型、固定版本 | embedding 替换实验 |
| Chunk | 同一切分规则 | chunk 大小和 overlap |
| 生成 | 同一回答模板、temperature=0 或固定值 | prompt/温度实验 |
| 检索 | Vector / Graph / Hybrid | top-k、社区层级、路径深度 |
| 统计 | 每条问题保存原始输出、证据和路径 | 按题型、文档、难度分组 |

### 6.1 公平性硬约束

Vector、Graph、Hybrid 必须使用同一原始数据、问题集、LLM、embedding、temperature、回答格式、评测模型和重试策略。每条结果额外记录上下文 token 预算、LLM 调用次数、输入/输出 token、索引耗时、查询延迟和估算成本，避免把模型、上下文长度或调用次数差异误认为图结构收益。

## 8. 结果解释和验收规则

结果表必须同时展示 Vector、Graph、Hybrid，不能只展示最好的方法。除了平均分，还要展示每种题型、延迟、调用量和失败样例。

如果 GraphRAG 的答案分数提高但证据召回不提高，需要检查是否是生成模型或 prompt 造成的假提升；如果答案分数下降但证据召回提高，需要检查知识注入和生成环节。任何结论都要能回到原始问题、检索上下文和参考答案。

## 9. 可复现命令和产物

Vector-only 第一版已经有正式运行入口：

```bash
set -a && source .env && set +a
./.venv/bin/python scripts/run_vector_baseline.py \
  --max-tokens 4000 \
  --output experiments/outputs/enron_s0/evaluation/vector_results.jsonl
```

该入口复用 S0 text units 和同一 Qwen embedding 服务，保存逐题答案、证据 source path、向量相似度、延迟、finish reason、token usage 和错误状态。GraphRAG、Hybrid 的正式入口完成后，也必须遵守同样的结果字段约定。禁止只在聊天中保留关键命令。每次正式运行至少提交：配置、运行入口、结果汇总 schema、失败样例索引和 README 中的当前状态。

Vector 与 GraphRAG Local 完成同题运行后，可执行第一层证据覆盖汇总：

```bash
./.venv/bin/python scripts/summarize_enron_results.py
```

该脚本只将 GraphRAG 的 `Sources (数字)` 按 S0 `documents.parquet` 的 `human_readable_id` 映射回邮件 `source_path`，再与 Vector 的 source path 对齐。它不把证据召回率当作答案正确率；答案正确性、忠实度、多跳成功率和路径召回仍需单独评测。

S0 当前严格统计仅用于发现问题：GraphRAG 可能通过同一邮件线程中的相邻邮件支持事实，但没有命中人工当前标注的主邮件；因此正式标注需要区分“必需证据”和“可接受证据集合”，并由人工复核后再计算最终 Evidence Recall。

## 10. 本组自有测试与评测闭环

上游不适用于本组环境的重型 workflow 已清理；这不代表最终系统只保留单元测试。本组后续必须补齐：

1. 集成测试：用临时目录和固定小数据验证文档、切分、图谱/向量索引和检索接口。
2. 端到端 smoke test：用 5–20 篇文档完成索引、建图、查询，检查答案非空、引用存在和预期实体至少被召回。
3. 统一评测：Vector/Graph/Hybrid 在固定问题集上保存逐题结果、证据、路径、指标、延迟和成本。
4. 失败归因：每轮改动都关联失败案例，复测时保留原始 baseline，不能只保留改进后结果。
