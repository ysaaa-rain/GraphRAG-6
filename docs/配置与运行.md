> 状态：517,401 封 Enron 邮件已完成统一预处理；本轮 California Power Crisis 已确定 66 封建库分母，上一轮 GraphRAG 索引生成了部分核心产物但尚未验收，Vector/Graph 对照待索引恢复并验收后开始。Medical GraphRAG 基线的建库、查询、generation 和 retrieval 已全部完成。

## 1. 已确认方案

- 生成、实体抽取、关系抽取和答案生成：DeepSeek V4 Flash API。
- embedding：本地部署 `Qwen/Qwen3-Embedding-0.6B`，不调用远程 embedding API。
- 运行系统：macOS 和 Windows 都要支持。
- Vector、Graph、Hybrid：共用同一 embedding、同一 LLM、同一回答协议，保证评测公平。

DeepSeek 官方文档提供 OpenAI 兼容的 API 调用方式，公开 API base 为 `https://api.deepseek.com`。Qwen 模型卡提供 Sentence Transformers 和 Transformers 的本地加载方式，模型默认维度为 1024，并支持调整输出维度。

参考：

- [DeepSeek 首次调用文档](https://api-docs.deepseek.com/)
- [DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
- [GraphRAG 模型配置说明](./config/models.md)

## 2. 密钥和环境变量

密钥只保存在每位成员本机的 `.env` 或系统环境变量中，不提交到 GitHub。建议统一变量名如下，具体字段以本组 embedding 适配层验证结果为准：

```dotenv
GRAPHRAG_API_KEY=请填入DeepSeek密钥
GRAPHRAG_API_BASE=https://api.deepseek.com
GRAPHRAG_COMPLETION_MODEL=deepseek-v4-flash

GRAPHRAG_EMBEDDING_MODEL=Qwen/Qwen3-Embedding-0.6B
GRAPHRAG_EMBEDDING_REVISION=97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3
GRAPHRAG_EMBEDDING_DEVICE=按本机硬件填写（当前 macOS 为 mps）
GRAPHRAG_EMBEDDING_DTYPE=float32
GRAPHRAG_EMBEDDING_DIMENSION=1024
GRAPHRAG_EMBEDDING_NORMALIZE=false
GRAPHRAG_EMBEDDING_ENDPOINT=http://127.0.0.1:8000/v1
```

DeepSeek 查询参数固定为非 thinking 模式、`max_tokens=4000`。Vector-only 基线必须使用相同参数；如果修改，必须重新运行三种检索方式，不能只修改其中一种。

真实 `.env` 不得提交。仓库只保存脱敏的变量名、配置模板、模型版本、验证日期和实验记录。

## 3. 跨平台约定

- 使用 `python -m ...`，不依赖 macOS 的 `./script.sh` 或 Windows 的 `.bat` 专用入口。
- 路径使用 Python `pathlib` 或配置中的相对路径，不把个人绝对路径写入代码和文档。
- 运行前检查 Python 版本、依赖锁定文件、API 变量和输出目录权限。
- 所有正式实验记录操作系统、Python 版本、GraphRAG commit、配置哈希和数据哈希。
- Windows 成员优先使用 PowerShell；命令文档会同时提供不依赖 shell 差异的 Python/uv 入口。

## 4. P1 接入顺序

1. 确认 GraphRAG 当前版本的模型配置字段和 LiteLLM provider 传参方式。
2. 用 DeepSeek API 完成一次最小 chat completion 验证，不发送课程数据。
3. 建立本地 Qwen embedding 服务/适配层，验证 `/v1/embeddings` 或等价内部接口能返回向量。
4. 固定模型 revision、设备、dtype、输出维度、归一化、pooling 和批量策略。
5. 用同一份最小文本同时完成 embedding、索引和查询验证。
6. 将脱敏配置模板、验证命令和结果写入本文件，再开始正式数据索引。

上述基础步骤已完成。正式索引配置和输出目录需在全量数据方案冻结后确定；运行前必须先把项目根目录 `.env` 导出到当前进程环境。

## 5. 资源与费用控制

- 配置未稳定前先使用不含课程数据的固定请求，避免消耗大量 API 额度。
- 首次正式实验固定并发、重试次数、最大输出长度和上下文 token 预算。
- 每次请求记录输入/输出 token、耗时、失败重试和估算成本。
- 不将 API 返回原文、密钥、缓存或大体积索引产物直接提交仓库。

## 9. 可切换方法与 trace 产物

Unified Search 左侧可以多选以下方法：`microsoft_local`、`microsoft_global`、`microsoft_drift`、`microsoft_basic`、`lightrag`、`hipporag2` 和 `hybrid_path`。自定义方法共享已有 Microsoft GraphRAG Parquet/LanceDB 索引，不要求重复建库。

每次查询成功后，系统会把实体、关系、图路径、子图节点、子图边、文本证据、source path、channel scores、`path_recall` 和 `evidence_recall` 写入当前数据集的 `output/retrieval_traces.parquet`。交互查询没有 gold path 时，两个 recall 字段为 `null`；评测时调用 `rag.retrieval.annotate_trace_metrics` 传入人工标注后再写回或汇总。

完整原理、参数、文件职责、前端交互和已知限制见[GraphRAG 方法调研与系统实现细节](./GraphRAG方法调研与系统实现细节.md)。
