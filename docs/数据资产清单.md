# 开放数据资产清单

> 状态：正式范围已收敛，具体数据仍需在下载前核验。没有完成来源、许可、版本、哈希和预处理记录的数据不能进入正式实验。

## 0. 正式范围与数量上限

正式实验只包含三组数据：

1. **GraphRAG-Bench Novel**：标准 benchmark。
2. **GraphRAG-Bench Medical**：标准 benchmark。
3. **Enron Email**：正式实际应用场景，要求大规模开放邮件语料。

Enron 不是只准备几封示例邮件：优先准备规模足够大的相互关联邮件语料，具体规模以下载、许可证、预处理成本和 API 预算共同确定。设计 20–30 道跨邮件问题，并选出 3–5 道代表性问题做最终可解释展示。

HotpotQA、MuSiQue、2WikiMultiHopQA 以及其他开放文本均属于备用/参考资产，当前不进入正式结果，也不在未确认范围前下载完整数据。

## 1.1 Enron 数据准入原则

Enron Email 是当前唯一正式实际应用场景，必须满足以下准入要求：

1. 记录准确的数据来源、下载日期、版本、文件哈希和使用条款。
2. 先审查邮件中的姓名、邮箱、组织信息、内部业务内容和潜在个人隐私风险，再决定保留范围和脱敏规则。
3. 保留原始邮件的来源标识、发件人、收件人、主题、时间和正文结构，确保跨邮件关系可以追溯。
4. 建立人员、部门、项目、事件、主题和邮件线程等实体/关系样例，验证它不是互不相关的邮件堆。
5. 为 20–30 道问题登记参考答案、原文证据、标准实体和标准路径。

对话中出现的“约 50 万封邮件”等规模描述暂不视为已验证事实；必须完成数据下载和清单统计后再写入正式数据记录。

## 2. 数据准入记录

每份数据必须有一条登记记录，至少包含：

- 数据名称、用途和所属实验。
- 原始来源 URL、发布组织和下载日期。
- 数据集版本、文件名、大小和 SHA-256 哈希。
- 许可证或使用条款，以及是否允许再分发。
- 文档数量、字符/token 数、语言、领域和预计图谱规模。
- 清洗、去重、切分、实体规范化和过滤规则。
- 可能的隐私、医学、版权、偏见或提示注入风险。
- 对应的 Git commit、配置和实验 ID。

## 3. 数据规模策略

“数据量上来”不能只等于下载大文件。本组采用三级数据规模：

1. S0 最小样例：几十 KB，用于代码和格式验证。
2. S1 小规模实验：GraphRAG-Bench Novel 100 题或少量文档，用于参数和失败分析。
3. S2 正式规模：Novel 全量、Medical 全量、Enron Email 的正式语料，用于正式结论。两个备用多跳 QA benchmark 不计入当前 S2 正式规模。

每一级都要记录图谱节点、边、社区、文本 chunk 和 embedding 数量，才能判断 RAG 效果变化是否和数据规模有关。

## 4. 数据管理规则

- 原始数据和模型缓存默认放在 Git 忽略目录或外部存储，仓库只保留下载/校验脚本、元数据和必要的小样例。
- 不提交密钥、个人信息、未经许可的完整作品、模型缓存和大体积中间文件。
- 公开数据也不等于可以无限再分发；许可未确认时只保存来源链接和哈希，不把原文复制进远程仓库。
- 任何预处理都要可重复，不能只保留人工修改后的最终文件。
