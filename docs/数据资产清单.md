# 开放数据资产清单

> 状态：正式范围已收敛，具体数据仍需在下载前核验。没有完成来源、许可、版本、哈希和预处理记录的数据不能进入正式实验。

## 0. 正式范围与数量上限

正式实验只包含四组数据：

1. **GraphRAG-Bench Novel**：标准 benchmark。
2. **GraphRAG-Bench Medical**：标准 benchmark。
3. **实际应用领域 A**：待确认，要求大规模开放语料。
4. **实际应用领域 B**：待确认，要求大规模开放语料。

实际应用领域不是只准备一篇示例文档：每个领域优先准备数百至数千篇相互关联的开放文档，具体规模以下载、许可证、预处理成本和 API 预算共同确定。每个领域设计 20–30 道问题，并选出 3–5 道代表性问题做最终可解释展示。

HotpotQA、MuSiQue、2WikiMultiHopQA 以及其他开放文本均属于备用/参考资产，当前不进入正式结果，也不在未确认范围前下载完整数据。

## 1.1 两个实际领域的选择原则

两个实际领域需要满足以下条件：

1. 原始文档数量足够，优先达到数百至数千篇，而不是只用几篇人工整理文本。
2. 文档之间存在可验证的实体、关系、主题或时间联系，能够检验 GraphRAG 的多跳和全局能力。
3. 数据来源、许可证、下载方式和版本可以记录，允许在课程项目范围内使用。
4. 两个领域的知识结构要有差异：一个优先关系密集、多跳明显；另一个优先跨文档、时间条件或全局总结。
5. 能够由本组为每个领域制作 20–30 道问题，并为每题登记参考答案、原文证据和标准路径。

当前推荐的默认组合是：

- A：AI/机器人等科研技术知识网络，以论文、作者、机构、主题和引用关系为主。
- B：公开政策、法规、政府报告或标准文档，以跨文档主题、时间和机构关系为主。

这只是待确认方案，不代表已经下载或锁定数据。确认前只进行来源调研和准入登记，不启动大规模抓取或 API 实验。

## 2. 数据准入记录

每份数据必须有一条登记记录，至少包含：

- 数据名称、用途和所属实验。
- 原始来源 URL、发布组织和下载日期。
- 数据集版本、文件名、大小和 SHA-256 哈希。
- 许可证或使用条款，以及是否允许再分发。
- 文档数量、字符/token 数、语言、领域和预计图谱规模。
- 清洗、去重、切分、实体规范化和过滤规则。
- 可能的隐私、医学、版权、偏见或提示注入风险。
- 对应的 Git commit、配置和实验 ID。

## 3. 数据规模策略

“数据量上来”不能只等于下载大文件。本组采用三级数据规模：

1. S0 最小样例：几十 KB，用于代码和格式验证。
2. S1 小规模实验：GraphRAG-Bench Novel 100 题或少量文档，用于参数和失败分析。
3. S2 正式规模：Novel 全量、Medical 全量、两个实际领域的正式语料，用于正式结论。两个备用多跳 QA benchmark 不计入当前 S2 正式规模。

每一级都要记录图谱节点、边、社区、文本 chunk 和 embedding 数量，才能判断 RAG 效果变化是否和数据规模有关。

## 4. 数据管理规则

- 原始数据和模型缓存默认放在 Git 忽略目录或外部存储，仓库只保留下载/校验脚本、元数据和必要的小样例。
- 不提交密钥、个人信息、未经许可的完整作品、模型缓存和大体积中间文件。
- 公开数据也不等于可以无限再分发；许可未确认时只保存来源链接和哈希，不把原文复制进远程仓库。
- 任何预处理都要可重复，不能只保留人工修改后的最终文件。
