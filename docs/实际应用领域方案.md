# 实际应用领域方案

> 文档状态：候选方案，待小组确认（2026-09-07）。
>
> 本文件只描述两个正式实际应用领域的选择依据和准备要求，不代表数据已经下载、许可证已经审核或实验已经开始。

## 1. 范围结论

正式实际应用只设置两个领域。每个领域都要独立完成：

- 数据来源、许可证、版本和 SHA-256 登记。
- 原始文档清洗、切分、去重和数据统计。
- 实体、关系、证据文本和图谱规模审计。
- 20–30 道自建问题及人工参考答案、证据和路径标注。
- Vector、Graph、Hybrid 的公平对照。
- 3–5 道代表性问题的可展开展示。

不再把增加领域数量作为主要进展。两个领域确定后，优先投入图谱质量、评测可靠性、失败归因和重复实验。

## 2. 推荐默认组合

### 领域 A：科研/技术知识网络

推荐优先选择 AI、机器人或其他计算机技术子领域，构建“论文—作者—机构—主题—方法—引用”的关系网络。

适合验证：

- 多实体关联：某作者参与了哪些研究，研究属于哪些主题。
- 多跳推理：作者—论文—机构—主题，或论文—引用—相关论文。
- 实体消歧：作者重名、机构别名、主题同义词。
- 图谱质量：引用方向、作者/机构归属、主题规范化和重复实体。

候选数据来源：OpenAlex 元数据与开放论文全文、arXiv 或其他许可证清晰的技术文档。最终只选择许可证、下载和规模均可核验的子集。

### 领域 B：政策/法规/政府报告

推荐选择一个机构或主题边界清晰的公开政策、法规、政府报告或标准文档集合。

适合验证：

- 跨文档关联：政策文件、主管机构、适用对象、时间和条款之间的关系。
- 时间条件：同一主题在不同年份的变化。
- 全局总结：多个文档对一个主题、机构或政策目标的共同描述。
- 证据解释：答案必须能回到具体文档、章节或条款。

候选数据来源：政府公开网站、法规公开数据库、标准或公共机构报告库。必须按页面或文件逐条核验使用条款，不能因为“网上可以访问”就默认可以再分发。

## 3. 选择门槛

两个候选领域都必须通过以下门槛，才允许进入正式实验：

| 门槛 | 要求 | 验收证据 |
|---|---|---|
| 规模 | 优先数百至数千篇相互关联文档 | 文档清单、数量、总字符/token 数 |
| 开放性 | 来源和许可证可核验 | 来源 URL、许可证页面、下载日期 |
| 关系性 | 存在可验证的实体和关系，不是互不相关的文章堆 | 实体/关系样例、跨文档连接样例 |
| 可评测性 | 能设计 20–30 道有明确答案的问题 | 问题草稿、参考答案、证据和路径 |
| 差异性 | A 与 B 的知识结构不同 | 领域特征说明和对比表 |
| 可复现性 | 数据可以通过脚本或固定清单重新获取 | 下载/校验脚本、版本和 SHA-256 |
| 风险可控 | 不引入未经授权的个人信息、敏感材料或无法说明的版权风险 | 风险登记和排除规则 |

## 5. 与标准 benchmark 的关系

GraphRAG-Bench Novel 和 Medical 是标准 benchmark，使用其官方 corpus、问题、参考答案和评测程序。两个实际应用领域使用本组自建问题和人工证据标注。两类结果分开报告，不能把自建领域的补充指标冒充 benchmark 官方结果。
