# Enron 实际应用方案

> 文档状态：正式应用方向已确认，S0 建库与首轮查询已完成；正式问题集和完整数据准入仍待完成（2026-09-07）。
>
> 本文件描述 Enron Email 在本项目中的应用边界、数据准备和评测要求。具体下载源、版本、许可证和最终数据规模必须完成准入核验后才能写成正式事实。

## 1. 应用定位

本项目将 Enron Email 作为唯一正式实际应用场景，目标是构建一个面向大型组织内部信息的关系增强问答系统：

```text
大规模邮件语料
    ↓
邮件清洗、线程整理和切分
    ↓
人员—部门—项目—事件—主题知识图谱
    ↓
Vector RAG / GraphRAG / Hybrid RAG
    ↓
跨邮件问题、证据、关系路径和答案
```

它与两个标准 benchmark 的分工不同：

- Novel：叙事型文本中的人物、事件和隐含关系。
- Medical：专业知识、治疗条件和决策链。
- Enron：大规模组织邮件中的人员、部门、项目、事件和跨邮件关系。

三个数据集形成差异化证据链，但正式数据集数量到此停止扩展，后续重点转向数据质量、评测和展示深度。

## 2. 计划验证的问题

Enron 问题集目标为 20–30 道，覆盖以下类型：

| 类型 | 示例问题方向 | 重点验证 |
|---|---|---|
| 单事实 | 某人负责或参与了什么事项 | 基本事实召回 |
| 多实体关联 | 某项目涉及哪些关键人物和部门 | 实体关联与证据覆盖 |
| 多跳推理 | A 与 C 没有直接通信时，通过哪些人或项目发生联系 | 图路径与跨邮件推理 |
| 全局总结 | 某事件在多个邮件线程中如何发展 | 多文档聚合和时间线 |
| 图结构帮助有限 | 单封邮件中直接出现的简单事实 | GraphRAG 的额外成本边界 |
| 幻觉风险 | 语料没有充分证据或问题前提错误 | 拒答、引用和忠实度 |

每道题必须保存：参考答案、支持答案的邮件 ID/文本片段、标准实体、标准关系/路径、问题类型和是否预期需要图结构。

## 3. 数据准入要求

### 3.1 当前核验到的来源

- 首选来源：CMU Enron Email Dataset 页面：<https://www.cs.cmu.edu/~enron/index.html>。
- 当前计划版本：页面标注的 `May 7, 2015 Version`，下载文件为 `enron_mail_20150507.tar.gz`。
- 下载地址：<https://www.cs.cmu.edu/~enron/enron_mail_20150507.tar.gz>。
- CMU 页面描述该版本约包含 150 名用户和约 0.5M 条消息；数据不含附件，部分消息因受影响员工请求而被删除或修订，部分无效地址也经过规范化。
- 2026-09-07 对下载地址执行 HTTP HEAD 得到 `Content-Length: 443254787`、`Last-Modified: Thu, 07 May 2015 20:35:29 GMT`。该大小只是服务器响应元数据，不替代下载后的 SHA-256。
- FERC 官方页面确认 Enron 邮件数据源自其调查材料，但具体可用版本仍以 CMU 下载文件和本组实际统计为准：<https://www.ferc.gov/electric/industry-activities/addressing-2000-2001-western-energy-crisis/information-released-enron-investigation>。

CMU 页面同时提醒该语料存在完整性问题、隐私风险和版本差异；本项目只把它作为公开研究语料，不把邮件内容当作法律事实或现实人物行为的结论依据。下载、解包和统计后，必须记录文件 SHA-256、邮件数量、用户数量、时间范围和解析异常。

## 4. 对照实验

在同一份 Enron 语料、同一批问题、同一个 DeepSeek V4 Flash、同一个本地 Qwen3-Embedding-0.6B 配置和相同回答协议下比较：

1. Vector RAG：邮件或邮件 chunk 的向量检索。
2. GraphRAG：实体、关系、邮件证据和路径增强检索。
3. Hybrid RAG：向量证据与图证据融合。

最终展示 3–5 道代表性问题，每道问题尽量完整呈现：

```text
问题
  ↓
Vector 检索到的邮件文本
  ↓
GraphRAG 匹配的实体、关系和路径
  ↓
两种方法的答案与引用
  ↓
参考答案
  ↓
成功或失败原因
```

重点不是预设 GraphRAG 在所有邮件问题上都更好，而是证明它是否能在跨邮件、多人物、多事件和组织关系问题上提供 Vector RAG 不容易得到的证据。

## 5. 数据与安全边界

- 原始邮件、处理后全文、模型缓存和大体积索引不提交 GitHub。
- `.env`、API 密钥、个人账号信息和本地路径不进入仓库。
- 对外展示时优先使用必要的脱敏文本、匿名实体或结构化摘要。
- 对无法确认许可或隐私风险的文件只保存来源、哈希和排除原因，不复制到远程仓库。
- Enron 的正式下载、清洗和入库脚本必须跨 macOS/Windows 可运行，并记录资源需求。

## 6. S0 建库与首轮查询记录

S0 只用于验证最小端到端链路，不作为正式效果结论。运行配置、完整日志和大体积索引均保存在被忽略的 `experiments/outputs/enron_s0/`，仓库只记录可复现的配置和摘要。

| 项目 | 已验证结果 |
|---|---|
| 输入 | 30 封邮件，转换为 33 个 text units |
| 图谱 | 480 个实体、1295 条关系、29 个社区报告 |
| 向量库 | `entity_description` 480 行、`community_full_content` 29 行、`text_unit_text` 33 行，均为 1024 维 |
| 生成模型 | DeepSeek V4 Flash API |
| embedding | 本地 Qwen3-Embedding-0.6B，revision `97b0c614…` |
| 首轮查询 | Local Search 成功，端到端耗时约 127.14 秒 |
| 首轮观察 | 能返回人物、组织、业务主题和 source/relationship 引用；尚未进行人工答案评分，也未与 Vector RAG 对照 |

首轮问题为：

> 这批 Enron 邮件样本中，哪些关键人物和组织被讨论？他们分别涉及哪些业务或日常事务？

回答主要覆盖 Enron、Continental Airlines、British Airways、加州能源政策，以及会议安排等线索。由于 S0 是从三个用户目录抽取的小样例，不能据此推断完整 Enron 语料的总体关系，也不能把模型生成的组织关系直接当作事实；后续必须回到原始邮件证据进行人工核验。
