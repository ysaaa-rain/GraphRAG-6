    基线说明

    1. 基线选择

    本项目首个代码基线选用 GitHub 上高 Star、文档和查询路径较完整的 GraphRAG 工程。选择标准是：能够覆盖知识图谱构建、向量/图结构化查询、LLM 知识注入，并且便于后续统一评测和解释。

    基线仓库：https://github.com/microsoft/graphrag

    截至 2026-09-05 的只读核查信息：

    • GitHub 页面显示约 35.6k stars、约 3.7k forks。
    • 许可证为 MIT。
    • 上游 main 当前导入 commit：f40e9a26ce62ba0b3fef8837d24aafdcc6e6c704。
    • 上游该 commit 日期：2026-08-24。
    • 上游 README 当前说明项目处于维护模式，主要进行 bug 修复和依赖更新；因此本组把它作为工程起点，不把其现状当作本组最终创新。

    2. 基线已经提供的能力

    从代码和文档核对到的能力包括：

    • 从非结构化文本抽取实体、关系和 claims。
    • 进行社区发现，生成多层级社区报告。
    • 生成文本向量并写入向量存储。
    • Local Search：以相关实体为入口，联合实体、关系、社区报告和文本片段回答局部问题。
    • Global Search：对社区报告进行 map-reduce，回答跨数据集聚合和主题问题。
    • DRIFT Search、Basic Search 和问题生成等查询路径。
    • 默认将索引输出为 Parquet 表，并把 embedding 写入配置的向量存储。

    3. 当前导入策略

    • 本地基线通过单分支浅克隆导入，固定上游 main 的当前快照。
    • 本仓库保留远程原有的 Initial commit，并用单独的合并 commit 记录“远程初始化状态 + 基线导入”的关系。
    • origin 指向本组远程仓库；upstream 指向上游仓库，后续同步必须经过检查，不能直接覆盖本组实验修改。
    • 基线原有许可证和版权文件保留在仓库中。

    4. 基线风险与验证要求

    基线文档明确提醒：索引过程可能产生较高 LLM 成本；不同版本之间可能需要重新初始化配置或迁移索引。因此在大规模运行前必须：

    1. 使用小样本验证依赖、模型、embedding、配置和输出格式。
    2. 记录模型、embedding、并发、chunk、token 上限、索引时间、调用量和失败重试。
    3. 对生成的索引表、实体、关系、社区报告和查询上下文做抽样检查。
    4. 使用同一套配置约束 Vector/Graph/Hybrid 对照，避免把模型或 token 数差异误认为检索方法收益。

    5. 参考的基线查询含义

    • Vector/Basic：从文本片段中选 top-k 相关内容，适合作为向量 RAG 对照。
    • Local/Graph：从实体出发扩展实体关系、社区报告和关联文本，适合特定实体问题。
    • Global/Graph：利用社区层级报告聚合回答全局主题问题，代价通常更高。
    • Hybrid：同时使用向量相似度、文本和图结构，作为实际系统中的折中候选。

    6. 不可直接照搬的内容

    基线中的默认 prompt、示例数据、依赖版本和默认参数不能未经验证地当作本组结论。所有本组修改都必须说明目的、影响范围、验证命令和下一步，并在变更记录中登记。
